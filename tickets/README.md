# Тикеты XMB

Файловый jira-like трекер: **один markdown-файл = один тикет**, всё в репозитории,
без облаков. Обзор — `tickets/board.html` (UI в браузере) и [BOARD.md](BOARD.md)
(то же текстом; оба генерируются, руками не править).

Перенесён из ainimator (`aispine`) как есть, с адаптацией префикса и областей.
Заменяет прежний `TODO.md`.

## UI — `tickets/board.html`

Открывается двойным кликом, без сервера и интернета. Генерируется командой `board`
(или `html`) и в git НЕ хранится — если файла нет, просто перегенерируйте.

- **Доска** — поиск и фильтры по приоритету, статусу и области; клик по строке
  разворачивает тикет целиком.
- **Ревью** — карточки всех `fixed`, сгруппированные по способу проверки. Для багов
  кнопки «✓ баг ушёл» → `verified` и «✗ баг остался» → назад в `open`; для остальных
  типов — «✓ работает как надо» / «✗ работает не так». Отметки живут в localStorage.
- **Новый фидбек** — форма для того, на что тикетов ещё нет.
- **Выгрузка для агента** — текстовый отчёт и готовые команды `tickets.ps1 set ...`.

Страница НИЧЕГО не пишет в репозиторий — браузер этого не может. Единственный путь
изменения тикетов — CLI, поэтому UI и выдаёт готовые команды.

**Агенты обязаны вести тикеты сами.** Баги, фидбек и решения пользователя иначе
теряются в переписке и стираются из контекста.

## Команды

```bash
powershell -File scripts/tickets.ps1 <команда> [аргументы]
```

| Команда | Что делает |
|---|---|
| `new -Type bug -Title "..." -Priority P1 -Area ui [-Source user] [-VerifyIn review] [-Labels watch] [-Note "..."]` | заводит тикет, сам берёт следующий ID и делает slug из заголовка |
| `set -Id XMB-0042 -Status fixed [-Commits abc1234] [-Note "что произошло"] [-Force]` | меняет frontmatter, обновляет `updated`, дописывает строку в «Историю» |
| `list [-Status open] [-Type bug] [-Area ui] [-Priority P0]` | таблица; без фильтров — только активные |
| `checklist` | «что проверить»: все `fixed`, сгруппированы по способу проверки |
| `board` | перегенерировать BOARD.md и board.html |
| `validate` | проверить все тикеты (выход 1 при ошибках) |
| `apply [-Path tickets/feedback.json]` | применить фидбек, сохранённый из board.html |

Frontmatter правится **только через `set`** — иначе `updated` и «История» разъедутся.
Тело тикета правится обычным редактированием файла.

## Поля

`id` `title` `type` `status` `priority` `area` `source` `verify-in` `created` `updated`
`links` `commits` `labels`

- **type**: `bug` | `feature` | `tech` | `decision` | `question`
- **priority**: `P0` (плеер не играет, виснет, не грузится) · `P1` (заметно портит
  работу) · `P2` (важно, но живётся) · `P3` (полировка, идеи)
- **area**:
  - `ui` — меню XMB, шторка, клавиатура, уведомления;
  - `player` — полноэкранный плеер, очередь, тексты;
  - `audio` — звуковой тракт, декодеры, эквалайзер;
  - `library` — скан, теги, обложки, плейлисты;
  - `net` — Wi-Fi, Bluetooth, xmbget, подкасты, LRCLIB;
  - `power` — сон, батарея, выключение;
  - `display` — панель, fb, частота кадров;
  - `input` — колесо, кнопки, тач;
  - `firmware` — `.upt`, оверлей, autorun;
  - `tools` — скрипты замеров, снимков, деплоя;
  - `docs`, `infra`.
- **source**: `agent` | `user` | `review-YYYY-MM-DD`
- **verify-in**: где подтверждается фикс — `review` (человек смотрит на плеере)
  | `test` (ПК-сборка, сценарий, замер) | `build` | `none`; обязательно для `bug` и `feature`
- **labels**: свободные метки; `watch` = «разово наблюдалось, следить»

## Статусы

```
bug/feature/tech/question:
  open → in-progress → fixed → verified
                         └─(ревью не подтвердило)→ open
  из любого: wontfix, cannot-reproduce, closed
decision:  accepted → superseded
```

| Статус | Смысл |
|---|---|
| `open` | разобрано, не начато |
| `in-progress` | агент работает прямо сейчас |
| `fixed` | **поправлено, НЕ проверено** — ждёт подтверждения по `verify-in` |
| `verified` | проверка подтвердила (терминальный для bug) |
| `closed` | терминальный для feature/tech/question и дубликатов |
| `wontfix` | решили не делать, причина — в «Историю» |
| `cannot-reproduce` | не воспроизвёлся; вернётся в `open`, если всплывёт |
| `accepted` / `superseded` | только для `decision` |

Терминальные статусы переоткрываются только через `-Force`.

## Петля ревью

Посмотреть на плеере, как это выглядит и ощущается, за агента нельзя:

1. Агент делает правку → `set -Status fixed -Commits <hash>`; в теле тикета — что
   именно смотреть и где.
2. Перед проверкой → `checklist`: список «что проверить».
3. Пользователь отмечает вердикты в board.html и жмёт «Сохранить фидбек в файл» →
   говорит агенту «оставил фидбек» → агент выполняет `apply`.
4. Подтвердилось → `verified`; нет → обратно `open` с записью, что именно осталось.

`fixed` ≠ `verified`. **Статус `verified` агент сам не ставит** — только по словам
пользователя. Замеры (fps, журнал, снимки экрана) агент проверяет сам и до `fixed`.

## Когда агент ОБЯЗАН завести тикет

- Пришёл пакет просьб или фидбек — по тикету на пункт.
- Пользователь принял решение в диалоге («делаем так», «это не трогаем») →
  `decision`-тикет **в ту же сессию**.
- Нашёл баг, который сейчас не чинит, — тикет вместо TODO в чате.
- Работу отложили («позже») — тикет.

## Когда агент ОБЯЗАН обновить тикет

- Начал работу → `in-progress`; сделал → `fixed` + `-Commits`, и `XMB-NNNN` в теле коммита.
- Узнал новое → запись в «Историю» (через `set -Note`).
- Конец сессии, если тикеты трогались → `board` + `validate`, закоммитить вместе с кодом.

## Чего агент НЕ делает

- Не ставит `verified` сам и не удаляет тикеты.
- Не правит BOARD.md руками.
- Не плодит дубли: перед `new` — grep по `tickets/` на похожий заголовок.

## Связь с другими документами

- **NOTES.md** — как устроено железо и код сейчас; `decision`-тикет — когда и почему так решили.
- **CLAUDE.md** — сжатая версия этих правил для каждой сессии.
